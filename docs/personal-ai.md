# Personal AI connections

In **Assistant → AI settings**, choose **Finance Studio AI** or **Use my own API key**. Personal connections support Google Gemini, OpenAI GPT, and Anthropic Claude. Choose a provider, enter a model ID available to that API account, and paste the provider's API key. API usage is billed by the provider; a consumer chat subscription is not an API key.

Personal keys stay in React memory in the current tab, scoped to the current authenticated session. They survive navigation and sheet changes, but clear on refresh, sign-out, account/session changes, key removal, or switching to Finance Studio AI. They are never saved in browser storage, financial records, Supabase, environment variables, or server-global state. Keys are masked in the settings dialog and can be removed at any time.

Each request sends the optional `personalAI` object over HTTPS in its JSON body, separate from chat/model context. The server verifies the signed-in user, email verification, request limits, and owned-sheet access before invoking a provider. The authenticated session determines which ledger is loaded; the settings cannot supply another owner's ID. Keys authenticate only that request and its bounded tool loop. Replies and application errors never return the credential or upstream error body. Provider endpoints are fixed and redirects are rejected. No custom API proxy/base URL is accepted.

A personal connection never falls back to shared site keys, another model, or a different provider. Switching back to Finance Studio AI restores the existing shared Gemini fallback behavior. Personal requests retain application request limits and the existing deadline and tool budget.

All providers use the same validated read tools, calculated financial evidence, transaction previews, proposed workspace changes, and PDF selections. Saving still requires the existing review controls. PDF and image attachments use each provider's native inline format; CSV/text attachments are decoded as untrusted text. OpenAI requests set `store: false`. Provider retention and billing remain subject to that provider's terms. Changing providers includes the current chat and relevant records with the next request; this is explained in the dialog and privacy policy.

Provider contracts: [Gemini generateContent](https://ai.google.dev/api/generate-content), [OpenAI function calling](https://developers.openai.com/api/docs/guides/function-calling), [OpenAI PDF inputs](https://developers.openai.com/api/docs/guides/file-inputs), [Claude Messages](https://platform.claude.com/docs/en/api/http/messages), and [Claude tools](https://platform.claude.com/docs/en/agents-and-tools/tool-use/define-tools).

Validation includes concurrent owners using different providers/keys, a later shared request inheriting neither credential, authentication rejection, personal connections without a configured shared key, error sanitization, quota isolation, native attachments, parallel tool IDs, valid draft/PDF/setup outputs, invalid tool arguments, and truncated responses. Provider HTTP responses are mocked in automated tests; paid live OpenAI/Claude generation requires the user's own working API account.
